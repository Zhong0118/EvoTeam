# EvoTeam PPT 总体设计与逐页制作说明

## 1. 本稿用途与制作分工

本文件直接维护正式汇报的设计源，取代旧提纲。组员可以按下面的文案、版式和素材编号制作 PPT；需要截图、姓名、日期和新实验结果的位置明确留空。本轮交付是设计文档，不是已生成的 `.pptx`。

暂按“老师/项目评审，12–15 分钟主讲＋问答”设计：14 页主稿、4 页备份。汇报时长、比赛模板和团队姓名尚未提供；这些只影响裁剪和视觉适配，不改变事实口径。主线为：**为什么需要跨任务改变组织 → 改变什么 → 如何以证据约束改变 → 当前实际做到了哪里。**

- B：文案与讲稿初稿、可编辑图形、页面排版、截图、数据图和导出；前端页面风格与 PPT 使用同一套颜色与状态标签。
- 负责人：审核文案、叙事节奏、结果与来源，确认是否具备“真实收益”结论，参与最终演练；不承担讲稿初稿或制作。
- A：架构、接口、运行/治理行为与失败路径核对，提供可读取的运行证据。

制作顺序：先完成 01–05、07–10、13–14 的结构和文案；06、11 留截图槽；12 可先填已核对的历史记录。B3 联调后补截图；N4 完成后决定是否整页替换实验结果，不为了凑结论强行晋级。

## 2. 事实标签与材料使用规则

每页右上角放一种来源标签，混合内容在对应区块另标：

| 标签 | 允许表述 | 使用方式 |
| --- | --- | --- |
| 已实现 | 能在当前代码找到并被测试覆盖的行为 | 注明核对的代码提交；不等同真实效果验证 |
| 历史实测 | 仓库保留的模型调用结果 | 注明日期、实验批次、样本数；不声称已在修复版重跑 |
| 机制示意 | 为解释概念而手绘的流程或故障 | 图内显式写“机制示意”，不填看似实测的数字 |
| 待补证据 | 尚未取得的截图、指标或因果结论 | 用浅灰占位框；正式上台前补齐或改成明确的下一步 |

模型名称只能沿用记录中的 `deepseek-v4-flash`，说明为“当时配置标识”，不据此宣称供应商最新能力。仓库记录有旧版错误归因及阈值为 1 的诊断案例，不能作为当前正确归因或经校准触发的证据。尤其不可把不可行任务失败说成“只要演进就能解决”。

不作无来源的竞品能力比较，不填质量提升百分比，不把测试数量当作业务成功率，不把 Token 换算成没有依据的人民币费用。

## 3. 整体视觉规范

### 画布与网格

16:9，1920×1080 设计稿；PPT 使用 13.333×7.5 英寸。下面所有坐标为百分比 `(x, y, w, h)`，原点在左上角。若制作工具使用英寸，x/w 乘 13.333%，y/h 乘 7.5%。页面标题、页脚和区块必须使用同一网格。

- 通用页标题：`(6,5,75,9)`；右上来源标签：`(82,6,12,4)`。
- 主内容区域：`(6,19,88,68)`；页脚来源：`(6,93,80,3)`；页码：`(90,93,4,3)`。
- 标题 32–36 pt，正文 20–24 pt，图内文字 17–20 pt，来源 11–12 pt；长来源写文件简称＋证据编号，完整路径放备注，不挤成小字墙。
- 中文优先思源黑体或微软雅黑，拉丁文用 Aptos，ID 用等宽字体。检查所有设备字体可用性；不使用只在制作者电脑有的装饰字体。
- 正文每页最多约 90 个汉字，图表标签除外；复杂解释写讲者备注。若超出，删句或移备份，不继续缩小字号。

### 颜色与图形

采用“证据与版本”的视觉主题：暖白底、深墨文字、青绿表示在线服务、紫色表示候选/离线过程。不要使用科技大脑、机器人头像或发光电路线作为主体。

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| 正文背景 | `F5F7F6` | 主体页面统一浅底 |
| 深色封面/结尾 | `142B2B` | 仅 01、14 页，文字 `FFFFFF` |
| 正文文字 | `18302F` | 标题和重点 |
| 辅助文字/线 | `62736F` / `D9E2DF` | 注解与坐标网格 |
| Current / 在线 | `187F72` | 同时带“Current/在线”文字 |
| Candidate / 离线 | `7660A8` | 不暗示已经上线 |
| 失败 / Reject | `B74A43` | 加 × 和状态文字，不能只靠红色 |
| 待采样 / 待证据 | `A87823` | 加空心菱形或“待采样” |

图形语义固定：Agent 为圆角矩形，确定性控制器为直角矩形，记录为带折角的文件形状，存储为圆柱。实线箭头表示当前路径，虚线表示拟议/条件路径并加文字。版本用 `project-planning@0`；候选对照可以并列，但正式服务版本线只有一条，不画 Family 树。

图使用可编辑的 PPT 原生形状；柱形/折线图优先原生图表。截图保持原比例裁切，最多一张主截图，重要区域用编号框指出。默认无动画；流程最多用 2–3 次出现，不能靠动画伪造正在运行。
