# 一、先判断这道题真正考什么

题目名称是：

> **基于 openJiuwen 构建具备自演进能力的多智能体协作系统**

这里实际上有三个层级：

```Plain Text
第一层：能不能做 Agent
             ↓
第二层：能不能让多个 Agent 协作
             ↓
第三层：Agent Team 能不能根据经验改变自己
```

其中：

**第一层、第二层属于基本分。**

真正拉开差距的是：

# 第三层——自演进。

因为官方在题目里直接用了：

> “自演进机制（核心）”

并明确列出了三种方向：

- 自动优化 Prompt / 工具使用
- 动态调整 Agent 数量或角色
- 基于历史表现改进策略

(competition.gitcode.com)

所以有一个很重要的判断：

如果最后做出来只是：

```Plain Text
Planner
   ↓
Researcher
   ↓
Writer
   ↓
Critic
   ↓
Result
```

虽然已经满足：

- 3 个 Agent

- Agent 分工

但是它本质还是：

> **固定 Workflow。**

这样的项目我会认为属于“完成了赛题，但没有真正吃透赛题”。

# 八、自演进我建议做成三个层级

这是整个项目最重要的设计。

## Evolution Level 1：Prompt Evolution

最容易实现，也是基本盘。

例如 ResearchAgent 初始 Prompt：

```Plain Text
你负责搜索资料，并总结与问题相关的信息。
```

运行几十个任务以后发现：

```Plain Text
FactChecker：

引用缺失：12 次
过期信息：7 次
来源质量低：9 次
```

Evolution Agent 总结：

```Plain Text
failure_pattern:
    citation_missing
    outdated_source
```

自动生成 Prompt V2：

```Plain Text
你是一名严谨的研究员。

要求：
1. 每一个关键结论必须有证据
2. 优先使用官方、一手来源
3. 对时间敏感信息必须检查发布日期
4. 不确定的信息明确标记
...
```

然后不是直接替换。

而是：

```Plain Text
Prompt V1
    vs
Prompt V2
```

跑验证集。

例如：

```Plain Text
              V1       V2

准确率        76%      87%
引用完整度    71%      91%
平均成本      1.0      1.08
```

达到阈值：

```Plain Text
Promote V2
```

否则：

```Plain Text
Rollback
```

这就非常像真正的软件/模型演进。

# 十一、甚至可以做到 Agent “裁员”

这个我特别建议做。

因为很多参赛作品很可能只做：

> 失败 → 增加 Agent。

> 那是不是 Agent 越多越好？

```Plain Text

使用率：8%

Evolution Engine：
收益 < 成本

→ Remove RiskAgent
```

于是：

```Plain Text

    ↓
4 Agents
```

结果：

```Plain Text
quality: 89.1 → 89.0
cost:    100% → 84%
latency: 100% → 79%
```

这个展示出来会非常漂亮。

因为它证明：

> **演进 ≠ 无脑增加复杂度。**

而是：

> **组织结构优化。**

# 十二、我建议不要上强化学习，一开始用“经验评分”就够

很多学生看到：

> Self Evolution

容易马上想到：

```Plain Text
RL
PPO
GRPO
Multi-Agent Reinforcement Learning
```

我暂时不建议。

复杂度太高。

我们完全可以用：

```Plain Text
Reward =
    Quality
  - λ × TokenCost
  - μ × Latency
  - γ × FailureRate
```

例如：

R=0.7Q+0.1S−0.1C−0.1LR = 0.7Q + 0.1S - 0.1C - 0.1L

其中：

- Q = 质量
- S = 成功率
- C = Token 成本
- L = 延迟

然后比较：

```Plain Text
Strategy A
Strategy B
Strategy C
```

历史表现。

以后如果我们还有余力，再加：

> Contextual Bandit / UCB / Thompson Sampling

进行 Team Strategy Selection。

这会比一开始上 RL 稳很多。

## 接下来我建议我们这样推进

现在先**不用 GrillMe**。

下一步我建议直接开始做一件特别实际的事情：

> **把这道题从“概念”落成真正的软件架构。**

也就是下一轮我们直接确定：

**前端、后端、openJiuwen、LLM、Agent Registry、Evolution Engine、Memory、Evaluator、数据库分别怎么放；Agent 怎么通信；历史经验怎么存；一次任务从输入到演进完整经历哪些步骤；以及代码目录应该怎么设计。**

然后我会把方案分成 **MVP 必做 / 冲奖必做 / 有余力再做** 三档，避免一上来设计得特别宏大却做不完。

等这版出来以后，我们再开一次 **GrillMe 模式**。那时候我会站在评委角度专门找漏洞，尤其攻击一句：

> **“你这个所谓自演进，本质上是不是几个 if + 改 Prompt？”**

如果我们的架构能扛住这个问题，这个项目的方向基本就立住了。
