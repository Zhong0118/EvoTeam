# 那到底谁判断 Strategy 性能？

这里我建议正式再引入一个很轻量的东西：

```Plain Text
StrategyMonitor
```

注意它不是 Agent。

它是一个聚合统计组件。

关系变成：

```Plain Text
Evaluator
= 给每个 Run 打分

StrategyMonitor
= 聚合很多 Run 判断 Current Strategy 是否异常

Validator
= 比较 Current 和 Candidate

EvolutionManager
= 根据上述结果管理整个 Evolution 流程
```

所以你问：

> “判定 Strategy 性能是不是第三条里的 EvolutionManager？”

更准确的答案：

> **不是由 EvolutionManager 自己计算。**
> 
> StrategyMonitor 负责长期性能判断，Evaluator 提供单次成绩，Validator 提供 Candidate 对比结果；EvolutionManager 是拿这些信息做流程决策的人。

这会更符合单一职责原则。

# Orchestrator

```Python
class Orchestrator:

    async def execute(
        self,
        task: "Task",
        strategy: Strategy,
    ) -> "RunResult":

        instances = self._create_instances(
            task=task,
            strategy=strategy,
        )

        for node_id in self._topological_order(strategy):

            instance = instances[node_id]

            upstream_context = self._collect_inputs(
                node_id=node_id,
                strategy=strategy,
                instances=instances,
            )

            instance.context.update(upstream_context)

            result = await self._invoke_agent(instance)

            instance.output = result

        return RunResult(
            task_id=task.task_id,
            strategy_id=strategy.strategy_id,
            strategy_version=strategy.version,
            agents=instances,
        )
```

这就是在线执行层。

        self,

        version: int,

```Python
class StrategyMonitor:

    def should_evolve(
        self,
        runs: list[SealedRun],
        policy: EvolutionPolicy,
    ) -> bool:

        if len(runs) < policy.window_size:
            return False

        resource_conflicts = sum(
            "resource_conflict" in run.failure_tags
            for run in runs
        )

        if resource_conflicts >= policy.repeated_failure_count:
            return True

        return False
```

这一段回答了你：

> 谁判断长期 Strategy 有没有问题？

**StrategyMonitor。**

# Validator

Validator 跟 Evaluator 不同。

Evaluator：

```Plain Text
一个 Run
→ 一个成绩
```

Validator：

```Plain Text
两个 Strategy
× 一批 Task
→ 比较结果
```

例如：

```Python
class ValidationResult(BaseModel):
    current_quality: float
    candidate_quality: float

    current_error_rate: float
    candidate_error_rate: float

    token_increase_ratio: float

    passed: bool

    reason: str
```

```Python
class StrategyValidator:

    async def validate(
        self,
        current: Strategy,
        candidate: Strategy,
        tasks: list["Task"],
        policy: EvolutionPolicy,
    ) -> ValidationResult:

        current_metrics = []
        candidate_metrics = []

        for task in tasks:

            current_run = await run_strategy(
                task,
                current,
            )

            candidate_run = await run_strategy(
                task,
                candidate,
            )

            current_metrics.append(current_run.metrics)
            candidate_metrics.append(candidate_run.metrics)

        current_quality = average_quality(current_metrics)
        candidate_quality = average_quality(candidate_metrics)

        token_delta = relative_token_change(
            current_metrics,
            candidate_metrics,
        )

        passed = (
            candidate_quality > current_quality
            and token_delta <= policy.max_token_increase
        )

        return ValidationResult(
            current_quality=current_quality,
            candidate_quality=candidate_quality,
            current_error_rate=error_rate(current_metrics),
            candidate_error_rate=error_rate(candidate_metrics),
            token_increase_ratio=token_delta,
            passed=passed,
            reason="candidate passed gate" if passed else "candidate rejected",
        )
```

# EvolutionManager 最后变得非常简单

这反而是好事。

```Python
class EvolutionManager:

    def __init__(
        self,
        store: ExperienceStore,
        monitor: StrategyMonitor,
        validator: StrategyValidator,
        policy: EvolutionPolicy,
    ):
        self.store = store
        self.monitor = monitor
        self.validator = validator
        self.policy = policy

    async def tick(
        self,
        strategy: Strategy,
        validation_tasks: list["Task"],
    ) -> Strategy:

        runs = self.store.recent_runs(
            strategy_id=strategy.strategy_id,
            version=strategy.version,
            limit=self.policy.window_size,
        )

        # 1. 当前没有足够证据，不演进
        if not self.monitor.should_evolve(
            runs,
            self.policy,
        ):
            return strategy

        # 2. 做 Failure Attribution
        attribution = analyze_failure(runs)

        # 3. 根据归因生成少量 Candidate
        candidates = generate_candidates(
            strategy,
            attribution,
            max_count=self.policy.max_candidates,
        )

        # 4. 独立验证
        for candidate in candidates:

            result = await self.validator.validate(
                current=strategy,
                candidate=candidate,
                tasks=validation_tasks,
                policy=self.policy,
            )

            if result.passed:

                candidate.status = StrategyStatus.CURRENT

                # 保存正向收益经验
                save_improvement_experience(
                    current=strategy,
                    candidate=candidate,
                    validation=result,
                )

                return candidate

        # 没有任何 Candidate 通过
        return strategy
```

你会发现：

> EvolutionManager 本身其实没有那么“智能”。

它更像：

```Plain Text

+
流程控制器
+
策略生命周期管理器
```

真正“智能”的部分只是插在其中的：

```Plain Text
analyze_failure()
generate_candidates()
```

这两个地方可以 Rule + LLM 混合。

# 最后给这套架构一句最简定义

现在整个 EvoTeam 可以明确分成 **在线执行面** 和 **离线演进面**：

```Plain Text
在线执行面

Strategy
↓
Orchestrator
↓
Team / AgentInstance
↓
Critic / Verifier
↓
Evaluator
↓
SealedRun
```

以及：

```Plain Text
离线演进面

SealedRuns
↓
Experience
↓
StrategyMonitor
↓
EvolutionManager
↓
Attribution
↓
Candidate
↓
Validator / ValidationGate
↓
Promote / Reject
```

其中：

> **Critic 判断“当前任务有没有做好”。**
> 
> **Evaluator 判断“这一次 Run 表现多少分”。**
> 
> **StrategyMonitor 判断“当前 Strategy 长期是不是出问题了”。**
> 
> **Validator 判断“Candidate 是否比 Current 更好”。**
> 
> **EvolutionManager 不负责亲自打分，它负责把这些东西串成一次受控的 Strategy Evolution。**
