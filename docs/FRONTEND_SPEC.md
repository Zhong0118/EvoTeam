# EvoTeam 前端设计与交互规范

本文件是本轮前端的唯一设计依据，供执行者 B 及其 Codex 实施。技术选型和以下设计为已确定的开发约定，不表示页面、依赖或接口已经实现。任务范围及 HTTP 数据契约见 [任务书 B](TASK_PRESENTATION.md)，PPT 页序与素材规则见 [PPT 设计](PRESENTATION_PLAN.md)。本文件不新增核心开发任务。

## 1. 产品定位与开发边界

面向项目组、评审和开发者的只读证据工作台。用户应能回答：一次任务产生了什么结果；团队如何执行；为什么提出或拒绝候选；当前服务哪个版本。首轮以中文界面、桌面演示为主，同时保证窄屏可阅读。

主路径：运行记录 → 任务详情 → 团队与 Trace → 关联演进 → Gate 决定 → 策略版本。只有真实关联引用存在时才显示可点击跳转；没有关联显示“暂无关联演进”，不按时间相近猜测关系。

允许浏览、筛选、查询刷新、历史回放、复制 ID 和下载脱敏证据。不会因浏览启动 Run/Evolve，不提供策略编辑、连线修改、手工晋级、模型配置、账户管理入口。Agent 可自行处理组件拆分和局部排版，不能改变页面结构、指标口径、来源标签或业务状态含义。

## 2. 固定技术栈与工程约定

| 层面 | 采用方案 | 用途及限制 |
| --- | --- | --- |
| 工程 | React + TypeScript（strict）+ Vite | 单页应用，放在 `frontend/`；现有 FastAPI 提供数据 |
| 路由 | React Router | 路由参数和 URL 查询参数保存可分享浏览状态 |
| 样式 | Tailwind CSS v4 | 通过统一 CSS 变量管理颜色、间距、圆角，不在页面散落不同主题 |
| 组件 | shadcn/ui，统一使用 Radix 基础组件 | Button、Table、Tabs、Sheet、Select、Badge、Tooltip、Skeleton 等按需引入；源码归项目维护 |
| 图标 | Lucide React | 图标与文字共同表达状态；纯图标按钮必须有可访问名称 |
| 拓扑 | React Flow（`@xyflow/react`） | 自定义只读节点、缩放、平移、适应画布；关闭连接和节点编辑 |
| 指标图 | Recharts | 对比柱图与有真实序列的趋势图；每图有等价数据表 |
| 数据请求 | 原生 fetch + 集中式数据源接口 | 统一处理取消、错误、DTO 校验；本轮不另引全局状态库 |
| 测试 | Vitest + React Testing Library；Playwright | 组件/数据适配测试与主要浏览路径测试 |
| 包管理 | npm，提交 package-lock.json | 使用兼容依赖版本，记录 Node LTS 具体版本；CI/他人安装使用 npm ci |
| 动画 | CSS transition + 显式回放状态 | 首轮不增加独立动画库 |

创建工程时将实际版本锁入 lockfile，在 frontend/README 记录 Node 版本、安装/运行/构建/测试命令。不得把“已确定选型”写成“已安装完成”。`shadcn` 初始化与生成代码也需检查主题和基础组件是否符合本文件，不能直接套用完整后台模板。

建议目录：`src/app/`（路由与布局）、`pages/`（四类页面）、`components/ui/`（基础组件）、`components/evidence/`（来源/状态/证据组件）、`data/`（DTO、fetch 与 fixture 适配）、`fixtures/`（开发样例）、`styles/`（设计变量）。页面只能通过 data 层读数据。前端环境变量仅保存公开连接地址，不保存模型密钥。

## 3. 视觉体系

### 3.1 设计方向

沿用 PPT 的“证据与版本”主题。浅灰绿背景、白色内容区、深墨文字；青绿表示 Current/在线，紫色表示 Candidate/离线。特点是证据链中的每个阶段都能展开来源，保留紧邻结论的证据入口。页面重点放在可追溯的过程与差异，不堆无来源的数字卡片、机器人插图或发光背景。

| CSS 变量 | 值 | 使用规则 |
| --- | --- | --- |
| `--background` | `#F5F7F6` | 页面背景 |
| `--surface` | `#FFFFFF` | 表格、抽屉和内容区 |
| `--foreground` | `#18302F` | 标题、正文 |
| `--muted-foreground` | `#62736F` | 次级说明；小文字需实测对比度 |
| `--border` | `#D9E2DF` | 内容分隔，不用作唯一焦点提示 |
| `--primary` | `#187F72` | 主操作、选中、Current 标记 |
| `--candidate` | `#7660A8` | Candidate 标签和比较区域 |
| `--destructive` | `#B74A43` | 失败、Reject；同时显示图标和文字 |
| `--pending` | `#A87823` | 待采样的边框/图标；正文用深色，避免浅底低对比 |

成功、失败属于运行结果；Current、Candidate 属于策略身份，不能共用一个字段或标签。Current 不代表成功，Reject 不等于运行失败。无证据使用中性灰和文字，不能显示绿色成功态。

字体：中文正文优先系统 PingFang SC / Microsoft YaHei / sans-serif；英文标题可用本地系统字体，ID/版本和数字用 ui-monospace。首轮不依赖在线字体。标题 28/36px，区块标题 18/26px，正文 14/22px，表头/说明 12/18px；关键表格数字启用 tabular-nums。正文不小于 14px，12px 只用于辅助信息。

间距采用 4/8/12/16/24/32px；卡片圆角 12px、输入框/按钮 8px。内容间以留白和 1px 分隔线组织，阴影仅用于浮层，不给所有卡片增加厚阴影。每个内容区最多一个主按钮，其余为次要按钮或文字链接。

### 3.2 全局布局

桌面参考尺寸 1440×900，并检查 1920×1080 截图。侧栏 216px，顶栏 64px，主区内边距 24px，区块间距 24px；超宽屏内容最大宽度 1600px 居中。

```text
┌──────────────┬───────────────────────────────────────────────┐
│ EvoTeam      │ 面包屑                 来源标签 / 采集时间     │
│              ├───────────────────────────────────────────────┤
│ 运行记录     │ 标题 + 简短说明              页面操作          │
│ 团队与 Trace │                                               │
│ 演进记录     │ 当前页面的核心证据内容                        │
│ 版本与指标   │                                               │
│              │                                               │
│ 数据来源说明 │ 缺失证据、样本范围、必要限制                   │
└──────────────┴───────────────────────────────────────────────┘
```

策略选择项取启动配置或已读取记录中的真实 strategy_id，不假设已有全量策略目录接口；来源不完整时标明“可用策略”。团队与 Trace 无已选 Run 时显示 Run 选择入口；版本页无策略时要求选择策略，不默认为“全局当前版本”。侧栏当前项有背景、文字和 aria-current，不能只改变颜色。

宽度 768–1199px 时侧栏收为 64px 图标导航，仍提供 tooltip 和可访问名称；小于 768px 改为顶栏菜单，内容单列。抽屉变全屏 Sheet；表格在自己的区域横向滚动，页面整体不横向溢出。拓扑保留缩放并提供文本事件列表，不缩小所有文字硬塞画布。检查 390px 窄屏。

## 4. 路由与公共操作

| 路由 | 内容 |
| --- | --- |
| `/runs` | 运行列表；默认入口 |
| `/runs/:runId` | 任务与运行详情 |
| `/runs/:runId/trace` | 团队拓扑与执行证据 |
| `/evolutions` | 演进记录列表，作为详情入口 |
| `/evolutions/:evolutionId` | 演进证据链与 Gate |
| `/strategies/:strategyId` | 正式版本与指标 |

列表筛选、当前详情 tab、选中节点等可恢复状态放入 URL；抽屉开关等临时状态留本地。浏览器后退应恢复筛选和已载入的浏览位置，不切回默认首页。切换数据来源时清除原来源的选择与缓存，避免相同 ID 混用。深链接不可用时展示原因和返回列表入口。

全局显示数据来源：fixture → “开发样例”；recorded_model_run → “历史实测”；current_database → “当前数据库”。当前数据库也可能包含旧代码记录，不能宣称是当前代码重跑。来源详情显示采集时间、代码提交（未知则说明未知）、引用和缺失项。来源入口用于查看说明；数据源按启动配置指定，首轮不做任意文件上传或服务地址编辑器。网络失败不自动切换成 fixture。

“刷新”只重新获取当前查询，不触发执行；“复制 ID”复制完整 ID 并反馈“已复制”；失败给出可选中文本。“下载证据”仅下载 B 的已实现脱敏导出结果，端口/适配未就绪时不显示可用按钮。内部系统路径、连接配置、密钥和原始 SDK 日志不得渲染或导出。

## 5. 页面一：运行记录与任务详情

### 列表 `/runs`

标题“运行记录”，副文案“查看任务结果及其执行证据”。标题下依次为策略筛选、用途筛选、刷新；主体为表格，列顺序：Run ID、任务类型、策略版本、用途、运行状态、评价结果、Token、耗时、封存时间、查看。

筛选只提供服务端已支持的 strategy_id/purpose；本轮接口没有全量状态筛选能力，不能对当前一页过滤后声称筛选了所有运行。若提供本地状态过滤，必须标“仅当前页”。默认每页 20 条，采用 cursor 上一页/下一页，不显示未知总页数；筛选改变后清空 cursor。末页按钮禁用，空页解释当前范围。

点击“查看”进入详情；ID 文本提供独立复制操作，不让复制冒泡打开详情。长 ID 省略显示但 tooltip/复制保留完整值。Token、耗时缺失显示“未提供”，不填 0；金额缺少明确金额、币种及来源时不按 Token 自行估算。

### 详情 `/runs/:runId`

```text
标题：任务详情 · Run ID       [查看 Trace] [下载证据（可用时）]
状态、用途、策略版本、数据来源
┌──────────────────────────────┬────────────────────────┐
│ 任务与计划（约 2/3）           │ 评价与用量（约 1/3）    │
│ 任务说明 / 约束摘要            │ 已记录结论、规则错误    │
│ 结构化计划表                  │ Token、耗时、终止原因   │
│ 人员 / 依赖 / 起止 / 产物      │ 证据引用与关联演进      │
└──────────────────────────────┴────────────────────────┘
```

任务类型/输入取 Task，计划取封存 Snapshot 中的实际产物，结果取 Evaluation，运行状态与用量取对应记录。计划区默认结构化表格；只有起止信息完整且单位明确才提供时间视图切换。点击错误引用可定位存在的计划行；引用不可解析时保留文字并说明无法定位。较长原始 JSON 放“查看结构化记录”折叠区，不能作为主画面。

只有索引没有快照时显示“该记录未提供完整任务快照”，保留可用状态/用量，隐藏不可用的计划图，不生成替代内容。运行终止、评价失败、缺少评价分别显示；不将运行正常结束等同于业务成功。

## 6. 页面二：团队与 Trace

标题“团队与执行证据”，副文案显示 Run ID 和固定配置版本。上方为 Run 选择/返回详情，主体左 2/3 为拓扑，右 1/3 为事件列表，下方为历史回放控制条。窄屏图在上、列表在下。

拓扑固定表示 AgentConfig 与配置连边；每个节点显示 Role、配置简称、实际实例数。实际执行实例在事件列表逐个列出；一次返工产生新实例，不能新增一种 Role。没有完整 execution_plan 时只展示可用事件列表，并说明缺少配置拓扑。

节点单击打开右侧 420px 证据抽屉：配置引用、实例选择、输入、输出、关联消息/工具事件（存在才显示）、状态及终止原因。多个实例必须显式选择，不能把最后一次输出当全部过程。选择事件同步高亮对应节点；无法关联节点的事件仍保留，不强行挂到某个 Agent。

提供缩放、适应画布、选择节点；禁止拖拽修改节点位置并保存、连线编辑和策略写操作。节点键盘可访问，同时提供事件列表作为图的等价导航。

回放控制包括“播放/暂停”“上一步/下一步”“回到开始”，常驻“历史回放”标签。按事件 sequence 排序，默认每 600ms 前进一个事件，显示“示意节奏，非实际耗时”；不按此时间计算延迟。播放只改变选中事件和图上强调状态，不改变真实业务状态。切换 Run、路由离开或数据源变化时停止计时器。缺事件时禁用回放并说明原因；不显示虚构进度百分比。

## 7. 页面三：演进记录与详情

列表标题“演进记录”，按策略查询，表格列：记录 ID、策略引用、Trigger、候选摘要、已记录决定、查看。使用实际返回字段；没有可靠创建时间就不显示推测时间。

详情标题“演进证据”，顶部显示演进 ID、Current/Candidate 引用和决定标签。下方是可点击阶段导航：Trigger → 证据与归因 → 候选差异 → 验证 → Gate。主内容左 2/3 展示所选阶段，右 1/3 为固定的“决定与依据”区域。窄屏决定区放在阶段导航之后。

| 阶段 | 具体内容 | 操作 |
| --- | --- | --- |
| Trigger | 实际信号、窗口/规则引用、关联记录 | 打开已有 Run 引用 |
| 证据与归因 | 支持样本、反例、Origin/Control 与限制 | 展开来源；不把归因陈述当独立事实 |
| 候选差异 | Current/Candidate 按字段并排，新增/删除/修改同时有文字标记 | 展开完整字段；不只显示红绿高亮 |
| 验证 | 已保存的配对/聚合指标、样本量、缺失项及公平比较限制 | 在有数据时切换汇总/逐题表 |
| Gate | 实际决定、规则引用、理由、证据不足项 | 跳转相关版本或 Run；无人工晋级按钮 |

阶段完成状态仅由存在的记录支持；没有记录显示“未提供证据”，不能凭最后一步存在就填满前面。Reject 使用明确标签“候选被拒绝”；待采样显示实际记录对应的表述，无候选显示“未生成候选”。Candidate 不能显示为已服务版本，Gate PASS 也不能自动推定已完成 Promote。

右栏优先显示已保存的决定和原因；没有 Gate 记录显示“尚无 Gate 证据”，不能自行推算 PASS/Reject。字段差异属于展示转换，可以根据两个实际对象计算；收益、成功率和裁决不得由前端另算。

## 8. 页面四：版本与指标

标题“版本与指标”，头部明确 strategy_id。上半区为单条正式版本线和版本详情；下半区左右两栏为候选比较与已有指标。Current 固定标签标识当前服务引用；只有历史服务证据充分时才称“曾服务”，否则仅称“已登记版本”。候选显示在独立比较区，不画成 Family 分支。

点击版本显示配置概要、Prompt/Tool 引用（数据存在才显示）、来源演进及相关 Run 入口；引用存在不等于能力已接入。比较选择最多两个版本/候选，展示真实配置差异；不可比较或缺指标时给出原因。

指标先以表格显示已有成功数/总数、Token、延迟、实例数、Retry 等明确字段；图表只绘制来源明确、同一实验口径的数据。当前接口没有提供全量汇总时显示“未提供汇总指标”，仍可展示版本与具体 Validation 的已存比较；不能遍历一页 Run 后生成全局看板。

每图必须展示单位、样本数、数据范围和实验/来源引用。Token 与金额不混用坐标轴；没有时序数据不画趋势。未知值留空并解释，不连接缺失点；少样本不画未经提供的置信区间。模型、预算或用途不一致时分组呈现并标“口径不同”，不输出收益结论。

## 9. 动画与状态规则

| 场景 | 规则 |
| --- | --- |
| 按钮、选中、hover | 150ms，颜色/边框/透明度；不缩放整张卡片 |
| 抽屉开关 | 220ms ease-out，轻微位移加透明度；关闭后焦点回触发点 |
| 页面与 Tab 切换 | 即时切换，最多 120ms 淡入；无逐块延迟入场 |
| 拓扑选中 | 150ms 边框/背景变化；条件边用虚线加说明 |
| 历史回放 | 仅选中事件变化；播放时可短暂强调对应边，无持续流光 |
| 图表 | 默认关闭数据入场动画，避免截图数字处于过渡状态 |
| reduced-motion | 关闭位移、淡入与边强调，仍可手动逐事件浏览；播放必须由用户启动 |

不自动播放、不在请求未完成时循环显示成功步骤、不用动画模拟模型正在执行。用户暂停后保持当前位置。

所有页面覆盖：加载（固定尺寸 Skeleton）、空列表（“当前条件下没有记录”及清除筛选）、404（ID 不存在及返回入口）、查询失败（简短原因及“重试查询”）、部分缺失（保留其余内容、局部提示）、离线（显示来源与最后成功读取时间，若无缓存则说明不可用）。重试只读请求；不隐藏错误后换样例。

按钮命名与结果一致，禁用操作说明原因。Sheet 管理焦点、Esc 关闭；Tabs、筛选和表格操作支持键盘；焦点边框清楚可见。正文对比度至少 4.5:1，非文本控件至少 3:1；验证实际组合，不仅检查色板。触控目标至少 44px。

## 10. B 的实施顺序与验收

1. B0：落实本文件设计变量、DTO、fixture 与数据源接口，记录已安装版本。四类样例为成功、失败、待采样、缺证据，并覆盖 null 和重复实例。
2. B1 首批：交付运行详情和团队 Trace 的可运行代表页面；提供 1440px 桌面、390px 窄屏截图，以及抽屉、空态样张。负责人检查视觉与操作是否符合本文，B 自行准备完整样稿。
3. B1 后续：复用同一布局和组件完成演进、版本页，补列表、导航、异常状态与历史回放。
4. B2/B3：沿用任务书的已有接口依赖接入真实证据；缺依赖继续用明确标记的 fixture，不修改核心模块或增加核心任务。
